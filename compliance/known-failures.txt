# Compliance cases the generated client is known to fail, as <suite>/<kind>/<id>.
#
# The suites are the cases smithy4s runs, and smithy4s is the reference for
# how simpleRestJson behaves: a case belongs here only when we deliberately
# match smithy4s rather than the test. Anything else failing is a bug to fix,
# not to list. The test run fails on any listed case that passes, so delete
# its line in the same change. `pnpm --filter smithy-ts-codegen-compliance run
# test` prints what each listed case currently gets wrong.

# --- Intentional: idempotency tokens are not filled in ---
# smithy4s leaves @idempotencyToken members to the caller, so that setting one
# is a conscious decision made outside of any retry loop.
restJson1/request/RestJsonQueryIdempotencyTokenAutoFill

# --- Not yet supported: alloy traits and constraint traits ---
# Unlike the case above, these are gaps rather than deliberate choices:
# smithy4s handles each of them. They fail the same way in a unary body, and
# show up here because smithy4s-ndjson's suite is the first to exercise them.
#
# @untagged unions are encoded and decoded as tagged ones.
ndjsonRestJson/events/NdjsonRestJsonRecordsUntagged
# @jsonUnknown on a structure's map member: unknown members are dropped on
# read and written nested under the map's name.
ndjsonRestJson/events/NdjsonRestJsonRecordsJsonUnknownStructureMembers
# Constraint traits (@range, @length, @pattern) and @uuidFormat aren't
# enforced on decoded values.
ndjsonRestJson/events/NdjsonRestJsonRecordsRejectsInvalidUuidOnClient
ndjsonRestJson/events/NdjsonRestJsonSubscribeRejectsOutOfRange
